# dbt Project: Public IPEDS

## Overview

This dbt project transforms raw IPEDS (Integrated Postsecondary Education Data System) completion and institutional data into a clean, dimensional data model optimized for analytics. The project follows the medallion architecture pattern (staging → intermediate → marts) to ensure data quality and maintainability.

## Data Layers

### 1. Staging Layer (`staging/`)
Staging models directly reference raw data sources and perform minimal transformations:
- Basic data type casting
- Column renaming for consistency

### 2. Intermediate Layer (`intermediate/`)
Intermediate models build upon staging models with business logic:

| Model | Description | 
|-------|-------------|
| `int_completions_by_year` | Union of completions across all survey years, filter on major_number = 1 |
| `int_institutions_by_year` | Union of institutional characteristics across all survey years |

### 3. Marts Layer (`marts/`)
Marts contain the dimensional model used for analytics and reporting. All mart tables are materialized as **tables** for performance.

#### Dimension Tables

| Model | Description | Primary Key |
|-------|-------------|------------|-------|
| `dim_award_levels` | Award level codes and descriptions (Associate, Bachelor, Master, etc.) | award_level |
| `dim_cip_codes` | CIP 2020 program classifications with STEM flags | cip_code |
| `dim_survey_years` | IPEDS survey years with corresponding academic years | survey_year |
| `dim_institutions` | Annual snapshot of institutional characteristics | institution_key (surrogate) |

#### Fact Tables

| Model | Description | Primary Key |
|-------|-------------|------------|
| `fct_completions` | Core fact table of student completions | completion_key (surrogate) |
| `obt_completions` | Denormalized completion data with all dimensions joined | — |
| `obt_completions_yoy_by_state` | Year-over-year completions analysis by state | — |

#### Data Model Features
- **Surrogate Keys:** Institution key generated by hashing survey_year and institution_id
- **Completion Key:** Composite surrogate key for fact table
- **Referential Integrity:** Foreign key relationships enforced via dbt tests
- **Grain Enforcement:** Unique combination tests on all fact and dimension tables

## Seeds (Reference Data)

Seeds are lookup tables loaded from CSV files:

### `award_level_codes.csv`
Award level classifications (e.g., Certificate, Associate, Bachelor, Master, Doctorate)

### `cipcode2020.csv`
Classification of Instructional Programs (CIP) 2020
- Note: CIP codes are stored as strings to preserve leading zeros (e.g. "01.0105")

### `ipeds_survey_years.csv`
IPEDS survey years and corresponding academic years
- Years covered: 2018–2024

## Macros

### `surrogate_keys.sql`
Generates surrogate keys for dimension and fact tables:
- **institution_key:** Combines survey_year + institution_id for unique identification

---

## Data Quality & Testing

The project implements comprehensive data quality tests:

### Test Types
- **Uniqueness:** Surrogate keys and natural keys
- **Not Null:** Critical business keys and dimensions
- **Referential Integrity:** Foreign key relationships between facts and dimensions
- **Unique Combinations:** Multi-column uniqueness constraints

Tests are defined in the model YAML files (`_int.yml`, `_mrt.yml`) and executed during `dbt build` runs.

## Materialization Strategy

| Layer | Materialization | Rationale |
|-------|-----------------|-----------|
| **Staging** | View | Minimal transformation, ephemeral in logical model |
| **Intermediate** | View | Clean code, efficient DAG, no redundancy |
| **Marts** | Table | Optimized for analytics queries, pre-computed dimensions and facts |

## Getting Started

### Prerequisites
- dbt installed (version 1.x or higher)
- Google BigQuery dataset named `dwh` or configured in profiles.yml
- Python environment with dbt dependencies

### Installation

1. **Set up the dbt environment:**
   ```bash
   cd dbt/
   dbt deps  # Install dbt packages (codegen, dbt_utils)
   ```

2. **Configure your profile:**
   Ensure your `~/.dbt/profiles.yml` includes:
   ```yaml
   public_ipeds:
     target: dev
     outputs:
       dev:
         type: bigquery
         project: [GCP_PROJECT_ID]
         dataset: [DATASET_NAME]
         threads: 4
         priority: interactive
   ```

3. **Run dbt:**
   ```bash
   dbt build             # Run models and tests (recommended)
   dbt run               # Run models only
   dbt test              # Run tests only
   ```

## Key Considerations

### CIP Code Handling
- **Issue:** `dbt seed` forces zero-padded codes as floats (e.g., 01.0105 → 1.0105)
- **Solution:** All CIP codes are explicitly cast as STRING in seed schema.yml

### Completion Data Filtering
- Only **first majors** (MAJORNUM=1) are included in completions data
- Secondary majors are excluded to avoid double-counting
- This aligns with standard IPEDS reporting practices

### STEM Classification
- STEM field definitions follow the U.S. Department of Homeland Security (DHS) Optional Practical Training (OPT) list
- See STEM classification here: [Link](https://studyinthestates.dhs.gov/stem-opt-hub/additional-resources/eligible-cip-codes-for-the-stem-opt-extension)

### BigQuery Optimization
- Mart tables are partitioned by year and clustered on common reporting attributes
